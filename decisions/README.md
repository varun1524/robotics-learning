# Architecture Decisions

Record choices that would otherwise be silently embedded in code. Use one
Markdown file per decision:

    NNNN-short-title.md

Each record contains:

1. title, date, and status;
2. context and measurable constraints;
3. options considered;
4. decision and rationale;
5. consequences and reversal cost; and
6. validation evidence.

Initial candidates include simulator mode, QoS profiles, canonical coordinate
frame, watchdog deadline, command-size limit, offline mission policy,
`MapVersion`/`MapRelease`/release-channel/mission-pin rules, and physical
hardware choice.

Never claim a hobby-system setting is a certified safety limit. Label measured
course targets as experiment-specific.
